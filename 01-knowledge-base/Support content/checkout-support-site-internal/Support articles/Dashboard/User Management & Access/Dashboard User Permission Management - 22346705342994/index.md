**When to use this article**

To support merchants who want to add, remove and modify user roles for Dashboard - the merchant can perform these actions via self-serve.

## INTRODUCTION TO DASHBOARD💬

Dashboard is where merchants can manage their Checkout account.

Merchants, or their account managers, may contact Merchant Care to request changes to user access on their dashboard. This includes adding new users, removing existing users, or changing the permissions of a user.

Merchants with "Owner," "Admin," or "IAM Admin" roles can manage users directly from their dashboard.

 

## KEY TAKEAWAYS 🔑

- Merchants should be directed to the [self-service documentation](https://support.checkout.com/hc/en-us/articles/16855651926418-Change-user-role-and-permissions-in-the-Dashboard) for all standard user and permission changes, especially for adding, updating or deleting dashboard users

⚠️ Support agents should **not** create new users or change user permissions on behalf of the merchant

- 
**Exceptions** exist for specific scenarios, such as when all owners and admins have left the business - in these cases, a request from an authorised signatory is required before taking action

## PROCESS FOR USER AND PERMISSION MANAGEMENT 🖊️

This process primarily involves directing the merchant to self-service resources except for the specific exception scenario.

**Step 1. Direct the merchant to the self-service option**

- Advise merchants that they can add, remove, or change user permissions directly through their Checkout.com Dashboard

- Provide a link to the relevant [self-service documentation](https://support.checkout.com/hc/en-us/articles/16855651926418-Change-user-role-and-permissions-in-the-Dashboard) for them to follow the steps themselves

- Inform them that support agents cannot create new users or change permissions on their behalf

- If an Account Manager (AM) submits the request, direct them to instruct the merchant to use the self-service guide

**Step 2. Handle exception cases (No active Admins or Owners)**

⚠️ If a merchant has no active Admins or Owners, they must provide a request from an authorised signatory

- Use **Genesis** to find the authorised signatory's information under the KYC/KYB section to verify the request

- Once verified, forward the request to the Merchant Configuration team

- Attach a screenshot of the authorised signatory's confirmation to the request if it was sent by an Account Manager

**❌ No action should be taken without confirmed authorisation from the signatory**

## ESCALATION** ⏫**

Requests from merchants where all Owners and Admins have left the business

**Required Information:**

- Merchant ID

- Details of the request (e.g. user to be added, role, email)

- Confirmation of the authorised signatory's approval 

**Instructions:**

- Stay on the case and monitor for updates

- Notify the merchant that the request has been escalated and provide them with the case ID for tracking

- Follow up with the Merchant Configuration team every 24-48 hours if no update is provided

 
 

## FAQs** ****❓**

Can I create a new user for a merchant?

No, per policy, support agents cannot create new users or modify permissions on behalf of a merchant. They must be directed to the self-service guide.What if the merchant doesn't have an owner or admin on the account?

If all Owners and Admins have left the business, you must obtain a request from an authorised signatory. You can verify this information on Genesis under the KYC/KYB section.Where can I find the authorised signatory's details?

Authorised signatory information is located on Genesis under the KYC/KYB section.What should I do if a commercial team member pressures me to create a user?

You should loop in a Merchant Care Leader to handle the situation and reiterate the policy that user creation must be done by the merchant or, in exceptional cases, with authorised signatory approval.
