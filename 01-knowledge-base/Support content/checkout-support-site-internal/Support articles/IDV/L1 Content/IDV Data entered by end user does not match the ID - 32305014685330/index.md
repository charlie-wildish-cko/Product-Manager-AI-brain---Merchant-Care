**When to use this article**

Use this when the decline reason in Looker is Mismatch Reference Data, this means the data entered by the end user does not match the data extracted from the ID document.

The Category is Verification Inquiry.

### **The issue 💬**

We have a reference data check feature enabled on the vast majority of our clients' user journeys (this is used to combat mass phishing). We compare the first and last names entered beforehand by users-which our clients send to us- against the same data found on the documents we analyze. 

  
We allow a certain level of tolerance for potential typos in the first and last names, but users sometimes enter names that do not appear on their ID document (for the date of birth, a strict match is required). In this case, you must check on **odash** whether the names entered match the extracted names and get back to the client. If in doubt, you may consult the Account Managers.
