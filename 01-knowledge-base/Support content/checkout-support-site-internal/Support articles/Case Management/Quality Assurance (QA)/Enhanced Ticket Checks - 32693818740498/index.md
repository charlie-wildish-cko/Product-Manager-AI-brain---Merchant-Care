### Two-Step Approval for Product & Workflow Tickets

**What is changing? **You can no longer solve tickets related to new products, workflows, or services without formal sign-off using the Zendesk Approvals app. This is part of our enhanced quality check process and once you are solving cases accurately you can solve cases independently.

**Why are we doing this?**

- Security: To protect merchants

- Compliance: To ensure we meet standards

- Accuracy: To prevent errors and technical delays

- Confidence: To give agents an extra layer of support whilst they are learning a new process

**Who is this guide for?** This document explains the exact steps for both the Agent (who requests approval) and the Approver (who signs off).PHASE 1: Agent Request for Approval

- **Ticket Selection:** The agent selects an open ticket for a new product or flow.

- **Initial Solve Attempt:** If an agent attempts to solve a ticket without approval, Zendesk will automatically reopen the ticket and display an internal note stating that approval is required.

- **Accessing the Approvals App:** The agent navigates to the **Apps** panel on the right-hand side of the Zendesk interface and selects the **Approvals** app.

- **Selecting the Flow:** From the dropdown menu, the agent selects request relevant to their workflow e.g. **IDV Approval Request**.

- **Adding Details:** A default message is pre-populated. The agent can then add specific context or notes for the approver in the message box.

- **Submission:** The agent clicks **Send**. This action automatically changes the ticket status to **Awaiting Approval** and adds an internal note indicating the process has started.

PHASE 2: Approver Review and Action

- 
**Notification:** The approver receives a notification via three possible channels:

  - A Zendesk notification pop-up.

  - An email notification with a direct link to the approval request.

  - The **Approval Requests** view in the Zendesk sidebar relevant to their workflow e.g. **IDV Approval Requests**.

- **Context Review:** The approver should click the **Ticket Link** within the approval window to review the full conversation history and context before making a decision.

- **Decision Entry:** Within the Approvals app on the ticket, the approver **must** provide a mandatory comment in the "Approve/Decline" box.

- 
**Final Authorization:** The approver clicks **Approve**. This adds a background tag to the ticket that technically enables the agent to solve the ticket.

  - **Decline:** The approver clicks **Decline** if more information is needed.

- **Ticket Reopening:** Regardless of the decision, the ticket reopens in the agent's queue. If approved, the agent will see a "Request Granted" note and can then proceed to solve the ticket.
